# FA v2: регистровый softmax, 16×32-плитка, ldmatrix (Q1.1)

Дата: 2026-11-22. Файлы: `engine/src/qwen35/q36_fa.cuh`, `engine/src/qwen35/q36_engine.cu`.
Дефолт не менялся (`--fa-tile 0` = 4×32); новые плитки — opt-in.

## Что сделано

1. **S.s убран**: счёт score пишется не в 4-байтовый shared-тиль, а экспонируется прямо из MMA-фрагментов (cq).
   Через shared идут только max/сумма по двум половинам колонок (`S.mx[Rows][2]`, `S.lsum[Rows][2]`),
   потому что половины warp'а владеют непересекающимися половинами колонок слайса.
2. **Плитка 16×32** (`--fa-tile 4`): 128 строк (16 запросов × 8 голов), 512 потоков, 96,8 КиБ shared.
   Блок обходит KV-префикс за 16 запросов вместо 4 — трафик K/V в 4 раза меньше.
3. **ldmatrix**: A-фрагменты (q, p) — `ldmatrix.x4`; B фрагменты K — `ldmatrix.x2` (K хранится [cell][hd]);
   B фрагменты V — `ldmatrix.x2.trans` (V хранится [cell][dim]). Скалярные `pack2`-чтения из shared убраны.
4. **p-запись half2** вместо двух half-store.
5. Диагностика: `STRATA_Q36_FA_PROF=1` — счётчики clock64 по фазам (K, score, softmax, p.v) для слоёв 0 и 47.

Точность (`STRATA_Q36_FA_CHECK=1`, сверка с cuBLAS-веткой): worst max_abs 4,2e-3, cos 1.000000.

## Вывод

- 16×32 + ldmatrix даёт −16 % fa и +13 % общего времени 160k под профилем; на 16k fa −17 %.
- Цель Q1.1 (fa 350–500 мс на 16k) **не достигнута**: остаток упирается в issue MMA (score+p.v 62 %) и softmax 24 %,
  а не в трафик K/V. Дальнейший рост требует другого класса изменений (крупные M-тили с переиспользованием B-фрагментов,
  отказ от барьера на слайс), а не настройки плитки. Q1.2 (KV-stationary split-K) issue не уменьшает.
- Дефолт остаётся byte-identical; 16×32 включается `--fa-tile 4`.
