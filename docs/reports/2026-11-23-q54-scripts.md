## UPDATE.bat (START-HERE.bat --update) — работает, форк-режим подтверждён

Первый прогон (rc=0): git pull своего remote, модели huihui/kat «up to date», движок не подменялся;
но setup остановился на «cmake / ninja not found after installing them».

Корень дефекта — окружение, не код: pip-лаунчер `terminal/.venv/Scripts/cmake.exe` сломался
(--version → rc=1, пусто), при живом модуле (`python -m cmake` → 4.4.3). find_tool в setup.py берёт
venv-лаунчер первым и отбрасывает нерабочий, а других кандидатов нет. Наш штатный build-скрипт ходит
в `site-packages/cmake/data/bin/cmake.exe` и не страдал никогда.

Починка: `pip install --force-reinstall --no-cache-dir cmake==4.4.3` — лаунчер ожил (rc=0).
Повторный UPDATE.bat (rc=0): пересборка `terminal/engine/strata.exe` из этого дерева (engine 0.1.66),
модели up to date. Подмены prebuilt нет — source=local компилируется, как и задумано для форка.

## build-verify.bat — легаси, на 0.2.16 layout не работает

Живой прогон: rc=2, «Системе не удалось найти указанный путь» — скрипт целит в старую E:-раскладку
(`E:\...\Strata-3060Ti\engine` как источник CMake и `E:\...\.venv` как тулчейн); на 0.2.16-раскладке
там нет ни CMakeLists.txt, ни .venv. В шапку файла добавлена пометка LEGACY; живой эквивалент
«собрать движок из этого дерева» — UPDATE.bat / START-HERE.bat --update (проверен выше) или
setup.py --build (Q5.2). patch_markers к этому файлу отношения не имеет (это CI-механизм, Q3.2).
