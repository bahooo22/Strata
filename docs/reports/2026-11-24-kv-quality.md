# KV-кэш: качество форматов (Q6.7) — методика и стенд, 24.11

Цель: выбрать формат KV для рабочего профиля (160k/200k) по КАЧЕСТВУ, а не только по скорости;
оценить ротированный fp4 и переход q4_0 -> q8_0 (нужен FDEC, стоит ~0,84 ГиБ VRAM на 160k).

## Стенд
- Промпт и force-последовательность: `terminal/tools/qwen35/parity_prompts.ids` (фиксированные ids),
  чтобы распределения сравнивались на одних и тех же контекстах.
- Два прогона на вариант: база `--kv-type fp32 --fdec 0` и тест `--kv-type <fmt> --fdec <0|1>`,
  одинаковые `--tokens`/`--force`, `--dump-full-logits` в файл (float32, шагами по V=248320).
- Скрипт: `glm/scripts/kv_quality_2026-11-24.py` (`--selftest` проверен; `--run` гоняет пару и
  считает KL(база||тест), top-1 и top-5 по шагам; результат — summary.md + raw.json).
- Правила прогонов: один сервер (tasklist до старта), логи в `glm/2026-11-23_session/kvq/`.

## Форматы и ожидания
| формат | VRAM на 160k | роль |
|---|---:|---|
| fp32 | 5,5 ГиБ | база сравнения (не рабочий профиль) |
| q8_0 | 1,78 ГиБ | пара к FDEC; проверяем цену качества |
| q4_0 | 0,94 ГиБ | текущий рабочий |
| q5_1 | 1,1 ГиБ | промежуточный |
| fp4 с ротацией | ~0,9 ГиБ | только вместе с KL (апстрим отверг неротированный: KL 5.19/13.30) |

## Допуски приёмки
- top-1: 100 % шагов базы; top-5: ≥ 92,5 % (37/40 при 8 шагах);
- KL mean/max: не хуже +10 % от базовой линии (база против себя — 0); абсолютные
  0.0115/0.0222 из таблицы апстрима — справочно, в отчёте рядом;
- смена дефолта (q4_0 -> q8_0) — только если KL-дельта в пределах +10 % И выигрыш tg от FDEC
  перекрывает потерю слотов экспертов (мерить «окно -> слоты -> tg», не «ядро -> tg»).
