# STAGING_ONE: фиксы F1/F2 по ревизии аналитика (2026-11-23)

Найдено аналитиком на приёмке `0a47d05de`/`e8009530a` (файл
`glm/2026-11-23_session/staging-one-down-sub8-review-2026-11-23.md`), подтверждено кодом и повторным замером.

## F1 — knob не уменьшал аллокацию

`staging_one` менял только план (`hin.staging_full = 1 x`), а аллокация резервировала два буфера
(`for b < 2`, :4269-4273). Теперь `n_stage = staging_one ? 1 : 2`, при одном буфере второй не создаётся.

## F2 — stream_done писал событие не в тот слот

`stream_kick`/`stream_take` под knob'ом берут слот 0, а `stream_done` писал `ev_used[stream_pos % 2]` —
на нечётных позициях ожидание в `stream_kick(p+2)` получало событие двухслойной давности (гонка: копия
могла стартовать раньше, чем ядра слоя p дочитали буфер). Теперь слот в `stream_done` тот же, что в kick.

совпали. Логи: sub8-on-run.log / sub8-off-run.log, дампы logits-sub8-on/off.bin.

проба подтверждает совпадение вывода, не различие путей.
