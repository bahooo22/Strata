# Отчёт о работах 20–23 ноября 2026

Форк Strata на ПК: **RTX 3060 Ti 8 ГБ видеопамяти, 32 ГБ оперативной памяти, Windows**.
Цель работ — довести локальный запуск MoE-моделей Qwen3.6-35B-A3B (сжатие IQ4_XS, файл 19 ГБ)
до рабочего состояния на **окнах 160k и 200k токенов** с приемлемой скоростью и без потери качества.

---

## 1. Словарь терминов и аббревиатур

| Термин | Что это простыми словами |
|---|---|
| **Strata** | Движок запуска больших MoE-моделей. Мы работаем на форке: 0.2.16 → 0.2.18 → 0.2.19 плюс свои патчи |
| **MoE** | «Смесь экспертов»: каждый токен проходит не через все веса, а через 2–8 из 48–256 подсетей-экспертов |
| **GGUF** | Формат файла модели: веса + метаданные. Наша модель — 19 ГБ |
| **IQ4_XS, Q4_K, Q5_K, Q6_K, IQ4_NL** | Способы сжатия весов, 4–6 бит на параметр. IQ4_XS — самый лёгкий из используемых |
| **prefill (pp)** | Чтение всего промпта; измеряется в токенах в секунду (tok/s) |
| **decode (tg)** | Генерация ответа по одному токену; измеряется в tok/s |
| **контекст, окно** | Сколько токенов модель держит в памяти за один запуск. Рабочие окна — 160k и 200k (204 800 ячеек) |
| **KV-кэш** | Память внимания. Хранится сжатой (q4_0, 4 бита), иначе 200k не помещаются в 8 ГБ видеопамяти |
| **attention (внимание)** | Механизм, где каждый токен «смотрит» на предыдущие. Занимал 57 % времени prefill |
| **FA, flash attention** | Блочное ядро внимания: считает кусками, без промежуточной матрицы оценок на весь контекст |
| **MMA, m16n8k16** | Матричная инструкция тензорных ядер NVIDIA: 16×8×16 элементов за такт |
| **ldmatrix** | Аппаратная загрузка фрагментов матриц из общей памяти под MMA напрямую |
| **shared-память** | Быстрая память одного вычислительного блока видеокарты (у нас ~95 КиБ на блок) |
| **occupancy** | Сколько блоков/потоков одновременно работает на одном мультипроцессоре |
| **issue-bound** | Ограничение скоростью выдачи инструкций, а не скоростью памяти |
| **int8 / fused** | Наши ускоренные ядра для prompt-экспертов: целочисленные умножения и «слитные» ядра формата |
| **P4** | Наш режим `STRATA_Q36_P4=1`: fused-ядра для prompt-экспертов, даёт +7,5 % prefill |
| **MAP / D1** | Наш кэш экспертов на медленном диске (`STRATA_Q36_EXPERT_CACHE_MB`) и чтение на шаг вперёд |
| **hybrid, pinned, staging** | Схема «эксперты в RAM, горячие — в VRAM»; закреплённая память; буфер загрузки слоя |
| **MTP** | Спекулятивное декодирование черновиком. У нас выключено (`--mtp 0`) |
| **PLE** | В модели Qwen3.8-Flash часть эмбеддингов хранится на диске (Per-Layer Embeddings) |
| **GDN, conv, RMS, RoPE, swiGLU** | Внутренние блоки слоя: свёртка, нормировки, поворот позиций, активация |
| **VRAM / RAM / PCIe / SATA** | Видеопамять 8 ГБ / оперативная 32 ГБ / шина между ними / медленный диск |
| **needle / QA** | Тест «иголка в стоге» (найти слово в длинном тексте) и набор вопросов качества |
| **ctx_sweep** | Скрипт поиска максимального окна перебором 96k…204k |
| **bench-pp / run_one** | Синтетический замер на случайных токенах и замер на реальном тексте (эталон) |
| **пин** | Принятая ранее лучшая скорость (0.2.16: 905 prefill / 15,2 decode на 160k) |
| **SelfTest, CI, dispatch** | Самопроверка скриптов упаковки; автосборка на GitHub; её ручной запуск |
| **Portable, BUILD.json** | Комплект «распаковал — запустил»; паспорт движка (версия, архитектуры, происхождение) |

## 2. Хронология

### 20 ноября — фундамент

- **Найдена причина падения int8 на 160k.** Формат сжатия down-матриц «23» (IQ4_XS) не имел ветки
  в int8-маршруте: токен уходил в формат Q2_0, и ядро читало мусор. После фикса int8 стал рабочим.
- **Поиск максимального окна** (ctx_sweep, шаг 32k): обе IQ4_XS-модели держат полное окно
  204 800 — «иголка» 6/6, вопросы качества 12–14 из 14, ошибок движка нет.
- **Составлен список рычагов ускорения** A1–A7 с прогнозами и правилом «один рычаг — одна точка 160k».
- Скорости дня: **842–848 prefill / 14–15 decode**.

### 21 ноября — качество и первый крупный выигрыш

- **Починено fused-ядро down IQ4_XS** (три причины: не создавались инстансы ядра, два диспетчера
  отправляли в чужой формат, не включались 256-значные блоки). Было NaN — стало 4,88 мс,
  ошибка 1,44e-02 (паритет с int8).
- **Включён режим P4** (fused для prompt-экспертов): **905,2 / 15,2** на 160k против 837,7 / 14,3
  без него (+7,5 %).
- **Профиль prefill**: внимание 57 %, эксперты 18 %, GDN 14 %, прочее 11 % — главный резерв понятен.
- **Выбор моделей** (hard-suite, 5 моделей): общая — Huihui IQ4_XS (0,864), код — KAT IQ4_XS (0,717).
  Лишние модели удалены, чтобы освободить диск.
- Сделан **префетч чтения экспертов (D1)** для SSD-режима.

### 22 ноября — большой день

- **Влит апстрим 0.2.18**: 160k **899,9–901,7 / 15,2**; MAP-режим **986,0 / 12,0**.
- **Qwen3.8-Flash (76 ГБ) запущена**: 7,2 prefill / 2,0 decode — для работы на этом ПК не годится
  (нужно ≥64 ГБ RAM или NVMe).
- **Сделана FA v2** — главная работа дня:
  убрана промежуточная матрица оценок, максимум и сумма строки живут в регистрах с обменом между
  двумя половинами колонок; добавлена плитка «16 запросов × 32 позиции» (блок обходит префикс
  вчетверо реже); операнды загружаются через ldmatrix, вероятности пишутся парами.
  На рабочем окне **200k (202 665 токенов): 641,7 → 745,3 tok/s (+16,1 %)**; на 139k — паритет с пином.
  Коммит `30d71e316`, тег `merged/fa-v2`.
- **llama.cpp**: ваш форк слит с апстримом (ветка с прежними коммитами сохранена), llama-server собран.
  Сравнение на том же промпте: **llama 159,9 prefill / 4,04 decode против Strata 900 / 15,2** —
  разрыв 5,6× по prefill и 3,8× по decode. Вывод: llama-портфель не обновляем.
- **Влит апстрим 0.2.19** (55 коммитов, новый движок inkling2): конфликтов ноль, наш q36-движок
  не тронут, скорость после мержа не изменилась (745,3 / 12,2).
- **Мелкие правки**: запрос сразу пишется в F16 (убран отдельный проход); переключатели частоты
  «перебалансировки» слотов. Гипотеза «чаще перебалансировка — быстрее декод» проверена и
  **опровергнута**: у дефолта 54,1 tok/s, у частых вариантов 51,7–52,8.
- **Portable**: llama-нога удалена, комплект переименован в **Strata-Portable**, `strata_kq.dll`
  убрана из манифеста. Самопроверки упаковки: 216/216 и 125/125.
- **Реестр маркеров патчей** обновлён: 29 маркеров, 166 наших коммитов.

### 23 ноября — фиксация

## 5. Ошибки и уроки

| Симптом | Причина | Что сделано | Урок |
|---|---|---|---|
| int8: illegal memory access на 160k | не было ветки down-формата 23 → уходил в Q2_0 | добавлена ветка `i8_launch<23,false>` | новый формат должен иметь ветку во всех маршрутах |
| fused: NaN | три причины (инстансы, диспетчеры, блоки 256) | все три исправлены | «тихий NaN» — это всегда маршрут, а не математика |
| Сборка llama.cpp падала на `acc.cu.obj` | путь передан как `/I` (стиль MSVC), nvcc ждёт `-I` | флаг исправлен, сборка 309/309 | не копировать флаги чужого компилятора вслепую |
| llama-server не стартовал | `-fa` требует значения `on/off/auto` | `-fa on` | сначала `--help` |
| 160k: «контекст не влезает» | не передавались `--att-mb 256 --kv-type q4_0` | взят пресет проверенного лаунчера | флаги — из скрипта, а не на глаз |
| Процесс движка иногда не выходит | фоновые потоки чтения | снимать `taskkill`, проверять `tasklist` | после каждого прогона — проверка процессов |
| **Дважды запускались два сервера параллельно** | не дождалась завершения первого | замеры пересняты по одному | правило: один сервер, `tasklist` до старта |
| 204k-замер: отказ 400 | промпт 209k токенов больше окна | мастер ужат до 616k знаков (~202,7k токенов) | движок честно отказывает, а не режет промпт |
| Субагент не закончил Q4 (лимит ходов) | слишком крупная задача | дочистила и проверила сама | дробить задачи, проверять диффы |

## 6. Форки и сторонние решения

Прочитаны и оценены **все 8 форков** из плана: XeStrata, Strata-V100, Lamina, CacheKV-kinoyu,
4gbVramStrata, StrataPool, StrataGP, lighttransport. Подробная таблица — в
`2026-11-20_23-forks-research.md`. Лучший по применимости — **Lamina** (4/5): Windows, одна карта,
35B-A3B, экспертные тиры с префетчем следующего слоя. У XeStrata лицензия **LGPL** — идеи читать
можно, код брать нельзя.

Сторонние движки: **llama.cpp** проверен прогоном (разрыв 5,6×); **inkling2** из 0.2.19 влит,
но не запускался; vLLM/ExLlama не рассматривались — не помещаются в 8 ГБ видеопамяти.
