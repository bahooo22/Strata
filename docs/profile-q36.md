# Профилировщик q36 (`STRATA_Q36_PROFILE=1`)

Сборка `e1002945`; профилировщик в `src/qwen35/q36_engine.cu` (в `layer()` вокруг миксера
и MoE; `cudaEvent` + синхронизация только при включённом env). Вывод — в `--bench-pp/tg`:
`profile: attn .. ms, gdn .. ms, moe .. ms` (stderr), счётчики обнуляются после каждого rep.

## Reserve (KAT 16k, pp 8192 / tg 64, cpu 4)

| `--vram-reserve-mib` | слотов | pp | tg | CPU-пул, с |
| ---: | ---: | ---: | ---: | ---: |
| 768 | 32 | 281.0–298.3 | 21.3–24.0 | 5.6 |
| 512 | 36 | **309.2–338.6** | **22.5–26.3** | 5.1 |
| 256 | 40 | 285.3–315.1 | 24.0–25.2 | 5.1 |

Меньше резерв → больше слотов экспертов в VRAM → быстрее и prefill, и decode (256 и 512
в пределах шума, оба лучше 768). Для 16k выбран 512 (36 слотов, запас на MTP). С MTP2 и
reserve 512: pp 316.4–331.8, tg 23.7–26.5 — профиль 16k переведён на 512.

На 80k (chunk 1024, MTP 2) наоборот: reserve 768 — 275.7/16.4, reserve 512 — 256.7/16.9;
prefill падает на 7 %. Для 80/96k запас под staging/KV нужен — там 768/1024; уменьшать
резерв только на коротких окнах.

## hybrid-rows (KAT 16k, chunk 1024)

`--hybrid-rows 1024` переводит prefill-чанк с PCIe-стриминга на слоты + CPU-пул: 4 потока
не справляются — prefill 8192 не завершился за ~5 минут (при default 128/streamed — ~30 с
на повтор). Оставить default 128.

## Волна 1 (03.11): pacc под T≤8 и L2-порядок split-K

- `att_rows = H * min(tmax, 64)` → `H * kGemmT` (8): split-K работает только при `T ≤ 8`,
  а `pacc` держал 64 строки — на 96k это 384 → 48 МиБ, освободившиеся 336 МиБ дали
  +6 слотов экспертов в VRAM.
- сетка `k_attn_part`: `dim3(nc, nt*H)` → `dim3(nt*H, nc)` — 8 q-голов одной KV-головы
  идут подряд и читают общий чанк K/V из L2.

| 96k (pp 32768 / tg 64) | pp | tg | CPU-пул | слотов |
| --- | ---: | ---: | ---: | ---: |
| baseline +1003 | 301.3 | 18.3 | 6726 мс | 17 |
| после правок | **326.2 / 325.8 / 325.1** | **23.3 / 23.7 / 23.5** | 4597 мс | **23** |

pp +8 %, tg +28 %; CPU-пул быстрее на 32 %, потому что больше экспертов осталось на GPU.

Слияние route-ядер (count+scan в одном блоке вместо трёх запусков) дало на 96k
pp 568.0/568.8/567.4 против 562–565, tg 20.9/21.7/21.5 против 18.6–21.1,
CPU-пул 5131 против 5395 мс; жадный вывод `--tokens` совпал.

`quantize_scatter` (T строк вместо T·Kp) проверен и **отклонён**: pp 285.6–311.7 против
325.1–326.2, tg 20.6–22.3 против 23.3–23.7, CPU-пул 5062 против 4597 мс — перестановка
записей дороже повторного чтения активаций. `swiglu_quant` недоступен: только SM60-сборка.
`ext` для `T > 8` тоже **отклонён**: pp +1 % (569 против 562–565), но tg 17.7–19.2
против 18.6–21.1 и GPU-доля 11.8 % против 25.6 % — fused router меняет выбор экспертов
на границах, роутинг уезжает.

Пример полного профиля (KAT 16k, pp 8192 / tg 64, граф отключён профилем): total 28.1 с,
moe 24.5 с, gdn 1.56 с, attn 0.80 с, head 0.071 с, quant 0.056 с — сумма секций 27.0 с,
остаток (embed, синхронизации, хост-работа) 1.1 с.

## Prefill chunk (04.11): 2048 вместо 1024, att-mb 64, reserve 512

Причина: prefill идёт чанками, и на каждый чанк эксперты каждого слоя заново копируются
в VRAM; при 1024 на 96k это ~90 полных обходов 41 слоя. Больший prefill-чанк сокращает
их число, а `--att-mb 64` и `--vram-reserve-mib 512` возвращают освободившиеся слоты.

| окно | было (prefill 1024, att 128, res 768) | стало (prefill 2048, att 64, res 512) | слоты |
| --- | ---: | ---: | ---: |
| 64k | 288.3 / 19.9 | **1026.8 / 21.7** | 28 |
| 80k | 275.7 / 16.4 | **1044 / 22.7** | 25 |
| 96k | 573.8 / 21.4 | **1053 / 24.0** | 24 |
| 128k | 648.3 / 14.0 | 648.3 / 14.0 | 7 |

- 128k: prefill 4096 не влезает (0 слотов экспертов, pp 586.2) — оставлен 2048.
- Биты: SHA greedy при prefill 1024 и 2048 совпадает (`34ff51c7b6320bbd`).
- Профили 64k/80k/96k переведены на новые параметры в `harness/config`.

## Ограничение

Профиль виден в `--bench-pp/--bench-tg` и в serve-DONE: при `STRATA_Q36_PROFILE=1` движок
после строки DONE печатает в stderr (лог движка) `profile: total … head … quant … attn …
gdn … moe … draft … verify … commit …` и обнуляет счётчики — доля каждого запроса.
`quant` — квантование активаций/выхода SwiGLU в MMQ-пути, `draft/verify/commit` — фазы
спекулятивного шага (хост-время с синхронизациями). При `STRATA_Q36_PROFILE=1` CUDA-граф
отключён: события нельзя записывать внутри захвата; без env синхронизаций нет.

Размер attention-буфера — флаг `--att-mb` (64…512; по умолчанию 256 МБ), переменная
`STRATA_Q36_ATT_MB` остаётся запасным путём; меньше буфер — больше слотов экспертов в VRAM.
