# gpu-infer-kit-2026-11-13: диагностика тюнинга окна (22.11)

Артефакт разложен: glm/artifacts/kit-2026-11-13/ (zip + распаковка).
Selftests: detect 10/10 OK; recommend selftest OK.

## Как kit выбирает окно

1) detect.py снимает GPU/RAM/диск; 2) recommend.py считает слагаемые по лесенке
64k..229376 (страта: KV + att + reserve + GDN + плотные веса; эксперты стримятся из RAM);
3) «реестр первичнее формулы»: max ЗАМЕРЕННОЕ окно модели из kit/models.json побеждает
формулу, если формула для него fits.

## Найдено на нашем ПК (3060Ti 8 ГБ)

recommend выдаёт окно 229376 (224k), basis=measured, правило
harness/config/strata-coder-224k.json. В реестре KAT IQ4_XS есть замер 229376 с pp 926,8 —
но он снят на СТЕНДЕ (VRAM почти наверняка 24 ГБ: эксперты помещаются в VRAM).
В реестре нет поля про VRAM/RAM стенда, поэтому замер переносится на любую карту,
где формула «влезает» — а на 8 ГБ это стриминг 16 ГБ экспертов из RAM (у нас 200k
реально 728 pp, 224k не мерили; на llama-ноге 224k деградирует).

Для модели, которой нет в реестре, берётся формула → снова max лесенки. Это и есть
«контекст всегда максимальный»; предупреждения о «не мерилось» в start.ps1 не видны.

## Оценка фикса (чинить, не переписывать)

Точечно (2–4 ч): (а) в реестр добавить vram_mib/ram_gib стенда и в measured_max
учитывать класс карты (иначе basis=formula); (б) в start.ps1 печатать basis/warnings
всегда; (в) selftest: «замер с чужой VRAM не выдаётся как measured». Переписывать
recommend.py не нужно (selftest и аудит уже есть).
Для точной причины на ПК пользователя (Ultra 225F/64 ГБ/RTX 5080) нужен артефакт:
  python kit\detect.py --out config.json
  python kit\recommend.py --gguf <модель> --config config.json --json > rec.json
и эти два файла.
