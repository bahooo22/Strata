# Levers tested and rejected (with numbers)

Reference machine: RTX 3060 Ti 8 GB, 32 GiB RAM, KAT IQ4_XS (qwen35moe), memory clock
+1003 MHz. q36 measurements at 96k unless stated; llama at 128k/96k with pinned host memory.

| Lever | What was tried | Result | Verdict |
| --- | --- | --- | --- |
| `quantize_scatter` for MoE activations | T embeds quantized once and scattered by `rinv` instead of T·Kp quantized copies | 96k pp 285.6–311.7, tg 20.6–22.3, CPU pool 5062 ms vs pp 325.1–326.2, tg 23.3–23.7, pool 4597 ms | slower: the scatter pass costs more than the 8× re-read it removes |
| `swiglu_quant` (fused SwiGLU + q8) | use the fused kernel instead of swiglu + quantize | compiled only in `STRATA_EXPERIMENTAL_SM60` builds | unavailable on sm_86 |
| `GGML_OP_OFFLOAD_MIN_BATCH=1` (llama) | run MoE on the GPU even for 1-token decode | pp 825.6 (better), tg 14.0 vs 18.9 (pinned `-ub 4096`) | rejected: PCIe latency per token beats the CPU path |
| `-ub 128` / `-ub 64` (llama) | fewer experts per ubatch to shrink H2D | prefill 133 tok/s vs 654–800 | rejected: MMQ efficiency dominates |
| `-ub 8192` at 96k (llama) | larger ubatch | pp 870.4 (+1 %), tg 20.7–20.8 vs 21.2–21.9 | use only at 128k (831.7/20.4 vs 800.5/18.9 at 4096) |
| `ext` router product for T > 8 (q36) | fused router + shared-gate row for prompt chunks | pp 569 (+1 %), tg 17.7–19.2 vs 18.6–21.1, GPU expert share 11.8 % vs 25.6 % | rejected: the fused product changes borderline top-k choices, routing shifts |
| `--hybrid-rows 1024` (q36) | move a prompt chunk from PCIe streaming to slots + CPU pool | prefill 8192 did not finish in ~5 min (default 128: ~30 s) | rejected: 4 CPU threads cannot feed it |
| `--pool-workers 4` / `8` (q36) | more CPU threads than the default 3 | 4: 309–339 pp / 22.5–26.3 tg; 8: 306–312 pp / 14.8–16.9 tg vs 336.9–345.9 / 25.5–26.0 | keep default 3 (4 physical cores, hyper-threading hurts) |
| `--vram-reserve-mib 512` at 80k (q36) | smaller reserve for more expert slots | 256.7 pp / 16.9 tg vs 275.7 / 16.4 at 768 | 80k/96k keep 768; 16k uses 512 (36 slots vs 32) |
| attention buffer 32M floats (q36) | smaller scores buffer for more expert slots | pp 243–308, tg 17.3–22.7 vs 289–312 / 19.0–20.4 | keep 64M (now `--att-mb 256`) |
| `STRATA_Q36_ATT_MB=128` after `pacc` (q36) | +3 slots at 96k before the `pacc` fix | 20 slots, pp 289–301, tg 17.9–19.1; after `pacc` the slot count is set by the arena, not this buffer | re-measure only when slots are the limit |

| GDN prefetch d=2 (q36) | two input sets, loads issued two steps ahead (bit-exact) | 96k `gdn_scan` 7,230.5 ms against 6,716.6 (PF=1), pp 1008 against 1019; 58 registers, 0 spill, same occupancy | rejected: the step was not waiting on memory - prefetch only hurts |
| GDN scan RG=8 (q36) | (32,8) = 256-thread block, one wave instead of two | `gdn_scan` 3,580.9 ms (-47 %), but the state: S max_abs 6.2e-4 (layer 1) -> 1.49 (layer 27) against the 1e-4 tolerance, cos down to 0.9956; KV/hlast diverge | rejected: the state drift across layers exceeds the tolerance (G3), although gen/needle held |
| RoPE cos/sin table per step (q36 patch B2) | fill a `[T][3][half]` table once per step instead of `powf`/`sincosf` per element | SHA diverges (tokens `198 220 220…` vs `1020 198 220…`), 96k pp 743.8/tg 17.3 vs 800.9/16.7, 128k 673.3/14.8 vs 673.0/15.5 | rejected: not bit-identical and slower |
| CUDA graphs (llama, `GGML_CUDA_GRAPH_NODES` counter) | count graph nodes/chunks to see if the decode graph is split | the counter never fires: `ggml_cuda_graph_check_compability` disables CUDA graphs whenever `MUL_MAT_ID` needs a stream sync, which is the case with `--n-cpu-moe` (PR #18958) | lever unavailable with CPU-offloaded MoE |
| Walsh–Hadamard rotation for q4_0 KV (q36 patch C, `STRATA_KV_WH=1`) | rotate q/k/v before q4_0 quantization to spread outliers | speed neutral: 1099.0/24.9 vs 1094.5/21.8 (96k, 3 reps); quality not measurable: its only carrier build (`build-c-only`) hallucinated on the 78k needle with the flag off as well (0/6 both ways), while the base build scores 1/1 (96k) and 3/3 (128k) | rejected: no speed gain, no proven quality gain, carrier build not equivalent to base on long prompts; retry only on a clean build |
| Merging GDN projections into one GEMM (qkv+zg+alpha+beta) | one matrix with n_out 12 352 instead of four calls | qkv is Q5_K (176 B/256 weights), zg is IQ4_XS (136 B/256), ssm_out is IQ4_XS with another input and K; only alpha+beta merge (both IQ4_XS): −1290 launches of 18 060 (−7.1 %), yet 0.055–0.06 s = 0.36–0.39 % of the 15.4 s GDN, 0.05–0.06 % pp | rejected: different ggml types per call (`Mat` has one `type` field), the gain is below noise |
| FA Q-ldg: Q read from global instead of shared (`k_fa_prefill`) | drop `S.q` to free 16 896 B and reach 4 blocks/SM | 96k tile 4x32: pp 1055.9 against 1341.1 of the FA pilot (<1307.3 = fail), although ptxas shows 128 registers / 0 spill and 4 blocks/SM; the k0 loop sits inside the slice loop, so Q is re-read on every slice — 768k warp-LDG per block (about 98 MB against 16 KB unique), and the LDG→MMA chain runs inside the iteration | rejected: the occupancy gain (at most 15 %) does not cover serialising the A-fragment load (−21 % pp); the next lever is 8x16 with Q back in shared (half the KV traffic) |

| Tile 8x16 with padding (kPad = 8) | a fifth `Slice = 16` variant with the old `kLD = 264` | shared 50 944 B → **1 block/SM** (2 × 51 968 = 103 936 > 102 400 with the 1,024 B per-block reserve), 124 regs; pp not measured | rejected on occupancy: it repeats 8x32 (1247.6) although its KV traffic is half of 4x32 |
| Tile 8x16 with LD = kHD (kPad = 0) | `Cfg::LD = kHD` for Slice 16: 49 664 B, 2 blocks/SM | 96k tile 4: **741.5 pp / 15.5 tg** against **1311.8 / 16.0** of the 4x32 control on the same build (−43.5 %); occupancy 2 blocks, 124 regs; G1 cos 1.000000; the cause is 8-way bank conflicts (stride 512 B ≡ 0 mod 32), while kPad = 8 (LD 264, stride 132 ≡ 4) removes them | rejected: the conflicts ate the traffic gain; kPad = 8 is required, but with it the tile gets 1 block |
| Double-buffered Q in shared (fa-qdouble) | `S.q[2][Rows][16]` plus one k0 step of prefetch; 26,368 B, 127 regs, 3 blocks/SM | G1 **red**: cos 0.7969, max_abs 2.24 — a race from the missing barrier between k0 iterations; pp/attn not measured — an accuracy failure | rejected: race; not reconsidered without a barrier between k0 iterations |
| Q in registers: 8 steps in `qreg[8][4]` + 8 through `__ldg` (fa-qregs) | Q loaded once per block for half the steps, the other half from global | 160 regs, shared 24,320 → 3 blocks (160 × 128 × 3 = 61,440); Q traffic 24 MB per block (+30 % of KV); 96k tile 0: 1291.8 pp / 16.6 tg against 1311.8 / 16.0 of the control — no gain; G1 cos 1.000000 | rejected: pp ≤ the control (1291.8 < 1311.8), the 1400 target is not reached |

Rule of thumb from these runs: on a hybrid MoE placement, moving bytes over PCIe or
reordering work inside the CPU pool rarely pays; removing VRAM waste (slots) and making
host memory pinned paid the most.
