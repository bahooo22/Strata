# Убрать ожидание `rmax` на каждом слое (q36)

**Статус:** идея, не реализована. Замерено как неприменимое к hybrid-раскладке.

## Где

`engine/src/qwen35/q36_engine.cu`, MMQ-путь промпта в `layer()`:

- `cudaMemcpyAsync(hpin + 10, rmax, 4, cudaMemcpyDeviceToHost, st)` и, для hybrid-слоёв,
  `cudaMemcpyAsync(h_cnt …)`, затем `cudaStreamSynchronize(st)` (в этом дереве
  q36:2324-2326).
- `rmax` — это `max_rows` из `k_route_scan` (q36:680-691), он передаётся как
  `Product::max_rows` обоим экспертным произведениям (q36:2334, 2342); MMQ выбирает
  по нему тайл `J` (`src/prefill/moe_mmq.cu`, выбор тайла `mmq:349-375`).

## Почему не применили здесь

- Тот же `cudaStreamSynchronize`, который доставляет `rmax`, доставляет и `rcnt`
  (числа по экспертам) для `hy[li].score` (q36:2336-2339). При 16.34 ГиБ routed-экспертов
  на 8 ГБ каждый промптный слой hybrid, поэтому sync нужен и без `rmax`.
- Идея окупается только когда основные слои целиком в VRAM (маленькая модель или
  раскладка `mtp_only`, где hybrid остаётся один MTP-блок — см.
  [mtp-only-prompt.ru.md](mtp-only-prompt.ru.md)).

## Дизайн для раскладки «всё в VRAM»

1. Верхняя граница `max_rows`: поставить `Product::max_rows = n_ent` (или
   `min(n_ent, tmax*Kp)`) и убрать D2H+sync. Сетка MMQ станет шире нужной; выбор тайла
   может дать другой `J`, и это может стоить дороже снятого барьера. Мерить оба варианта.
2. `rmax` на устройстве: хранить значение в памяти GPU и читать его при запуске MMQ;
   сегодня API принимает host-`int`, поэтому нужна правка API MMQ (поле «device pointer»
   в `Product`).
3. Отложенный `rcnt`: если score нужен раз на запрос (в non-hybrid он не используется),
   копировать `rcnt` один раз за `forward`, а не на слой. `rmax` при варианте 1 всё
   равно нужен на хосте для запуска.

## Проверка

- A/B 16k и 96k (`--bench-pp 32768 --bench-tg 64`), полный GGUF; приёмка pp +5 %, decode −2 %.
- Сравнить вывод токен-в-токен (`--tokens 1,2,3 --n 24`): неверный `max_rows` молча
  обрежет строки эксперта.
- Проверить выбор тайла в логе MMQ: меньший `J` проявится как замедление prefill.

## Риски

- Слишком маленький `max_rows` теряет строки (неверный ответ без ошибки); верхняя
  граница должна быть точной или больше.
- Более широкая сетка — накладные на коротких промптах (16k), где MoE уже 91 %.
