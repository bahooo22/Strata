# Промпт MTP-блока через MMQ + staging (q36)

**Статус:** идея, не реализована. На референсной машине недостижима (эксперты не влезают).

## Где

`engine/src/qwen35/q36_engine.cu`:

- `E.main_hybrid = !mtp_only` (q36:3266); в раскладке `mtp_only` основные слои держат
  всех экспертов в VRAM, а hybrid — только MTP-блок.
- `hy_rows = lhy(li) && (T <= hybrid_t || !main_hybrid)` (q36:2307): `!main_hybrid`
  отправляет **любой** батч MTP-слоя на слоты + CPU-пул, включая промптные чанки.
- Staging выделяется только при `E.use_mmq && E.main_hybrid` (q36:3271-3272), а
  `stream_begin` для MTP-слоя обусловлен `main_hybrid` (q36:2442).

## Эффект

Промптный чанк 32768 токенов MTP-блока считается CPU-пулом. В hybrid-прогонах на этой
машине пул занимал 6–8.6 с на чанк 32768 по всем слоям; для одного MTP-слоя тот же путь —
это вся стоимость промпта. Потоковый MMQ-путь прочитал бы экспертов MTP-слоя один раз
по PCIe (сотни МиБ) и посчитал на GPU.

## Дизайн

1. Выделять staging при `E.use_mmq` (а не только `main_hybrid`); размер как сейчас,
   `2 * (max_layer + kMmqTail)` (q36:3271).
2. В условии `hy_rows` убрать `|| !main_hybrid`, когда staging есть: чанки `T > hybrid_t`
   MTP-слоя пойдут через MMQ; батчи `T <= hybrid_t` сохраняют GPU+CPU-раздел.
3. Расширить `stream_begin` (q36:2438-2452) на последовательность MTP-слоя, когда он
   единственный hybrid; `stream_take`/`stream_done` уже учитывают `lhy(li)` (q36:2330, 2344).
4. Если VRAM не вмещает staging — оставить `mtp_only` без него (сегодняшний путь).

## Проверка

- Бит-в-бит драфты MTP: `--mtp 2 --draft-vocab 8192` и `--tokens … --n 64`, сравнить
  вывод с правкой и без; число принятых драфтов должно совпасть.
- `--bench-pp` на маленькой модели, где эксперты основных слоёв влезают (только там
  достижим `mtp_only`), затем диалог на полном GGUF.
- Следить за VRAM: staging — 2 × самый большой слой; на карте, куда эксперты еле влезли,
  может понадобиться запас `--vram-reserve-mib`.

## Риски

- Драфты MTP-блока питают спекулятивное окно; изменённый путь должен быть бит-в-бит,
  иначе accept-rate поменяется молча.
- Staging может увести плотную раскладку в OOM; fallback обязателен.
