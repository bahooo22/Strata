# Отклонённые рычаги (с числами)

Референсная машина: RTX 3060 Ti 8 ГБ, 32 ГиБ RAM, KAT IQ4_XS (qwen35moe), память
+1003 МГц. Замеры q36 на 96k, если не сказано иное; llama на 128k/96k с pinned host-памятью.

| Рычаг | Что пробовали | Результат | Вердикт |
| --- | --- | --- | --- |
| `quantize_scatter` для активаций MoE | T эмбеддингов квантуются один раз и раскладываются по `rinv` вместо T·Kp копий | 96k pp 285.6–311.7, tg 20.6–22.3, CPU-пул 5062 мс против pp 325.1–326.2, tg 23.3–23.7, пул 4597 мс | медленнее: проход scatter дороже 8-кратного перечитывания, которое он убирает |
| `swiglu_quant` (SwiGLU + q8 одним ядром) | fused-ядро вместо swiglu + quantize | собирается только в `STRATA_EXPERIMENTAL_SM60` | недоступно на sm_86 |
| `GGML_OP_OFFLOAD_MIN_BATCH=1` (llama) | MoE на GPU даже для decode в 1 токен | pp 825.6 (лучше), tg 14.0 против 18.9 (pinned `-ub 4096`) | отклонено: латентность PCIe на токен хуже CPU-пути |
| `-ub 128` / `-ub 64` (llama) | меньше экспертов на ubatch, чтобы сократить H2D | prefill 133 tok/s против 654–800 | отклонено: эффективность MMQ важнее |
| `-ub 8192` на 96k (llama) | больший ubatch | pp 870.4 (+1 %), tg 20.7–20.8 против 21.2–21.9 | только для 128k (831.7/20.4 против 800.5/18.9 при 4096) |
| `ext` роутера для T > 8 (q36) | fused router + строка shared-gate для промптных чанков | pp 569 (+1 %), tg 17.7–19.2 против 18.6–21.1, доля экспертов на GPU 11.8 % против 25.6 % | отклонено: fused-произведение меняет пограничные top-k, роутинг уезжает |
| `--hybrid-rows 1024` (q36) | перевести промптный чанк со стриминга PCIe на слоты + CPU-пул | prefill 8192 не завершился за ~5 мин (default 128: ~30 с) | отклонено: 4 CPU-потока не прокармливают |
| `--pool-workers 4` / `8` (q36) | больше CPU-потоков, чем default 3 | 4: 309–339 pp / 22.5–26.3 tg; 8: 306–312 pp / 14.8–16.9 tg против 336.9–345.9 / 25.5–26.0 | оставлен default 3 (4 физических ядра, hyper-threading вредит) |
| `--vram-reserve-mib 512` на 80k (q36) | меньше резерв — больше слотов экспертов | 256.7 pp / 16.9 tg против 275.7 / 16.4 при 768 | 80k/96k оставить 768; 16k — 512 (36 слотов против 32) |
| attention-буфер 32M float (q36) | меньше буфер score — больше слотов | pp 243–308, tg 17.3–22.7 против 289–312 / 19.0–20.4 | оставить 64M (теперь `--att-mb 256`) |
| `STRATA_Q36_ATT_MB=128` после `pacc` (q36) | +3 слота на 96k до правки `pacc` | 20 слотов, pp 289–301, tg 17.9–19.1; после `pacc` число слотов задаёт арена, а не этот буфер | перемерять только когда слоты — ограничитель |
| Таблица cos/sin RoPE на шаг (патч B2, q36) | заполнять таблицу `[T][3][half]` раз на шаг вместо `powf`/`sincosf` на элемент | SHA расходится (токены `198 220 220…` против `1020 198 220…`), 96k pp 743.8/tg 17.3 против 800.9/16.7, 128k 673.3/14.8 против 673.0/15.5 | отклонено: не бит-в-бит и медленнее |
| CUDA-графы (llama, счётчик `GGML_CUDA_GRAPH_NODES`) | считать узлы/чанки графа, чтобы понять, режется ли decode-граф | счётчик молчит: `ggml_cuda_graph_check_compability` отключает CUDA-графы, как только `MUL_MAT_ID` требует синхронизации потока, а с `--n-cpu-moe` это так и есть (PR #18958) | рычаг недоступен при CPU-оффлоаде MoE |
| Поворот Уолша — Адамара для q4_0 KV (патч C, `STRATA_KV_WH=1`) | поворачивать q/k/v перед квантованием q4_0, чтобы размазать выбросы | скорость нейтральна: 1099.0/24.9 против 1094.5/21.8 (96k, 3 повтора); качество измерить не удалось: единственный носитель (`build-c-only`) галлюцинировал на 78k-игле и с выключенным флагом (0/6 в обоих режимах), тогда как базовый build даёт 1/1 (96k) и 3/3 (128k) | отклонён: ни скорости, ни доказанной пользы, а сборка-носитель не эквивалентна базе на длинных промптах; повторять только на чистой сборке |


Практическое правило из этих прогонов: на hybrid-раскладке MoE пересылка байтов по PCIe
и переупорядочивание работы в CPU-пуле редко окупаются; больше всего дали снятие
пустой траты VRAM (слоты) и pinned host-память.
