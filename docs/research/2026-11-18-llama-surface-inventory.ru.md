# Что Strata на самом деле компилирует из llama.cpp (замер 18.11.2026)

Зачем: вердикту по compat-порту MMQ нужно число, а не ощущение. Фразу «головы почти не
касается» можно использовать только если три поверхности зависимости посчитаны и пересчитываются.

Мерка: `glm/scripts/strata_llama_surface_inventory_2026-11-18.py` (самотест - 9 проверок).
Читает `compile_commands.json` каждого дерева: этот файл перечисляет ровно те единицы перевода,
которые сборка поставила в работу. Каждая единица классифицируется по префиксу пути
относительно двух корней - корня движка и `STRATA_GGML_DIR` из того же `CMakeCache.txt`.
Всё, что легло вне обоих корней, рвёт мерку, а не подмешивается в молчаливую корзину.

Сопоставляемые деревья:

| | пин (`3cf03257f`) | новая голова (`llama.cpp` master) |
|---|---|---|
| дерево | `F:\tmp\sync1622-build-strata` | `C:\Projects\Strata-3060Ti\engine-v2\build-api-v2` |
| единиц перевода | 291 | 292 |
| из движка | 244 | 244 |
| из ggml | 40 | 41 |
| сгенерировано (trellis tq-оверлей) | 7 | 7 |

## Поверхность 1 - компилируется из llama.cpp

40/41 единиц, форма одинаковая в обоих деревьях: `ggml/src` 11, `ggml/src/ggml-cpu` 11,
`ggml-cpu/amx` 2, `ggml-cpu/arch/x86` 2, `ggml/src/ggml-cuda/template-instances` 14.

CUDA-часть - 14 единиц, и список между деревьями совпадает по именам целиком:
`mmq-instance-{q2_0, iq2_xxs, iq2_xs, iq2_s, iq3_xxs, iq3_s, iq4_nl, iq4_xs, q2_k, q4_k,
q5_1, q5_k, q6_k, q8_0}.cu`. Ни одного `mmvq-instance-*.cu` не компилируется - decode вообще
не пользуется decode-ядрами головы.

Разница составов пин → голова: `+ ggml/src/ggml-cpu/tiled/tiled.cpp`,
`+ ggml/src/ggml-cpu/tiled/tiled-kernel.cpp`, `- ggml/src/ggml-cpu/iqp.cpp`. Все три - CPU,
ни одна CUDA-единица не добавилась и не исчезла.

## Поверхность 2 - заморожено ручным портом

Порт несут 3 единицы, одинаковые в обоих деревьях: `native_mmvq.cu` (свой decode Страты),
`mmq_kq_lib.cu` и `mmq_kq_loader.cpp` (ABI-мост к вендорной dll). Вокруг них оверлей
генерирует 7 tq-инстансов, а собственная CUDA-поверхность движка - 48 единиц. Всё это код
Страты, и ни один апстримный коммит его не обновляет.

## Поверхность 3 - не участвует

`.cu`-файлы под `ggml/src/ggml-cuda`, посчитанные рекурсивно: пин 188 (120 инстансов + 68
ядер), голова 208 (135 + 73). Компилируется 14 в обоих случаях. Не компилируется 174 из 188
(пин) и 194 из 208 (голова) - 93 % CUDA-дерева головы.

## Помеха: записанный ggml-корень пина больше не существует

`F:\tmp\sync1622-build-strata\CMakeCache.txt` по-прежнему говорит
`STRATA_GGML_DIR=C:/Projects/Strata-3060Ti/llama-3cf`, и этой копии на диске нет. Мерка
подставляет вендорный пин `engine/third_party/strata-llama` (коммит `463940282`) и доказывает
подстановку по именам: 38 записанных ggml-единиц, 0 из них отсутствуют в подмене. Сам
бинарный носитель пина (`strata-q36.exe`, `strata_kq.dll`) цел; потеряно другое -
перенастроить то дерево нельзя, пока `STRATA_GGML_DIR` не переведён на живую копию.

## Следствие для решения по порту

Провал `tg` на новой голове не может прийти из CUDA-кода головы: голова даёт 14 компилируемых
CUDA-единиц, и это те же файлы и имена, что на пине. Круг кандидатов тем самым ограничен:
собственный ABI-путь порта `mmq_kq`, конфиг-таблицы и форма аргумента `tile_spec`, которые
открывает новая голова, и флаги компилятора дерева.
